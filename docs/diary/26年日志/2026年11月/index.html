Agent 自动化操作浏览器MCP Tool（Remove dependence of Playwright）

Playwright 是由微软（Microsoft）开源的一个现代化 Web 自动化框架，主要用于端到端（E2E）测试，但也广泛用于爬虫、脚本编写和 AI 代理等工作流。 它允许开发者通过代码控制浏览器，模拟真实用户的操作，如点击、输入和导航。

Playwright 并非“不好”，它在人类驱动的确定性 E2E 测试领域依然是最佳选择之一。 但在 Agent 场景下，它的“重”是一种范式级的错配：它为通用性和人类可读性付出的成本（巨大的 Token 开销、多层抽象延迟、完整浏览器冗余），恰好落在了 Agent 最稀缺的资源（上下文窗口、延迟预算、并发成本）上。

新方案的趋势，是从“为 Agent 提供一个完整的浏览器自动化框架”，转向 “为 Agent 提供一个专为机器认知优化的执行环境”——无论是通过直连底层协议、复用真实用户环境，还是从零构建一个只服务于 Agent 核心指标的精简引擎。OpenCode Browse 的巧妙之处在于，它用最小的侵入性，把“认证”这个 Agent 的最大负担，通过“人机接力”巧妙地卸载给了人类。

可以download一下源代码，看看 openCode browser 实现原理是什么？

用 Chrome 扩展的 chrome.debugger API 取得页面的 CDP 控制权， relay 在本地把这个能力同时封装成两种接口——自定义WebSocket 命令协议（给扩展管理）和标准 CDP DevTools 端点（给 Playwright/patchright 连接）， 再在上面套一层 MCP 服务器和沙箱化的execute 引擎。 相比直接用 Playwright 启动隔离浏览器，这条路换来的是：用户的登录态、扩展、cookie全部真实可用，且用户全程可见、可接管。
