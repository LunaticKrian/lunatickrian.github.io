确认当前 MiniKube 的执行环境是否是 containerd：

kubectl get nodes -o wide

minikube   Ready    control-plane   2m42s   v1.35.1   192.168.49.2   <none>        Debian GNU/Linux 12 (bookworm)   6.12.76-linuxkit   containerd://2.2.1

为什么推荐使用 containerd？

  • 支持安全沙箱容器：containerd 提供了灵活的扩展机制，能够支持 gVisor、KataContainer 等具有更强隔离性的“安全沙箱”容器。这些沙箱容器拥有独立内核，能提供更好的安全隔离。
  • 更轻量、更高效：与完整的 Docker Engine 相比，containerd 作为更专注的容器运行时，资源占用更少，启动速度更快。
  • 社区与版本趋势：Kubernetes 社区和阿里云官方都推荐使用 containerd 运行时。

MiniKube 本地 registry是什么？

Minikube 的本地 registry，本质上是一个运行在 Minikube 集群内部的私有容器镜像仓库。

本质是一个 Pod：Minikube 通过其插件（Addon）机制，在 kube-system 命名空间下，以一个普通的 Pod 形式运行了一个标准的 Docker Registry 服务。

  • 导出方法：使用 minikube image save 将镜像保存为 tar 文件
  • 在其他 Docker 环境中加载，可以将这个 .tar 文件复制到任何安装了 Docker 的机器上，并使用标准命令加载：docker load -i my-app.tar

K8S中的这个charts是什么资源？

Helm Chart 并不是 Kubernetes 的原生资源（Resource），而是 Helm 这个 Kubernetes 包管理工具所使用的 “软件包”格式。

工作原理：Chart 如何变成 Pod？

Chart 本身只是一堆文件，它通过 Helm 的工作流程，最终在集群中创建出我们熟悉的各类 Kubernetes 资源。

  1. Chart 是“模板”：Chart 中的 templates/ 目录存放的是 Kubernetes YAML 文件的模板，其中包含可被替换的变量。
  2. Values 是“配置”：values.yaml 文件为这些变量提供了默认值，你可以在安装时用自定义的 values 文件覆盖它们。
  3. Helm 进行“渲染”：当你执行 helm install 命令时，Helm 客户端会将 Chart 中的模板和你的配置 values 结合在一起，渲染出完整的、有效的 Kubernetes YAML 清单文件。
  4. 最终“创建”资源：最后，Helm 会通过 Kubernetes API 将这些渲染好的 YAML 文件提交给集群，从而创建出我们熟悉的 Deployment、Service、ConfigMap 等 Kubernetes 原生资源。

Chart 长什么样？ 一个典型的 Helm Chart 是一个包含特定文件的目录，主要结构如下：

my-chart/
├── Chart.yaml          # 必选：包含 Chart 的元数据，如名称、版本、描述等[reference:18]
├── values.yaml         # 必选：Chart 的默认配置值[reference:19]
├── charts/             # 可选：存放该 Chart 依赖的其他子 Chart[reference:20]
├── crds/               # 可选：存放自定义资源定义（CRD）[reference:21]
└── templates/          # 必选：存放 Kubernetes 资源的模板文件[reference:22]
    └── NOTES.txt       # 可选：安装后的使用说明[reference:23]

启用内部镜像仓库​

registry​

  • 在启动 Minikube 时，通过 --addons 参数直接开启：
minikube start --addons registry
  • 对已运行的集群启用，如果集群已经启动，可以使用 minikube addons 命令开启：
minikube addons enable registry

查看 registry 的IP地址：

kubectl -n kube-system get service registry -o jsonpath='{.spec.clusterIP}'

Harbor​

Harbor 企业级容器镜像仓库的事实标准

https://github.com/goharbor/harbor
